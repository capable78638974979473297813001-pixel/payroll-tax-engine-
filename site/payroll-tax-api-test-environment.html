Payroll tax API test environment

Two ways to try the real engine before you spend anything.

Many test environments return canned data. This one does not. The browser calculator and the test keys run the same engine and the same rule files as production, so a number you see while testing is a number you will see live.

The browser calculator

The calculator takes an address or a state, pay, a Form W-4 and deductions, and shows every tax line with a one-line explanation. It also shows the exact request it sent, as JSON and as cURL, so you can paste it into your own code and get the same answer.

Test keys

A test key lets your own code call the API. It needs no card and is never billed. It is capped at 30 requests a minute and 500 a day, which is plenty for development and for a CI run.

What a test environment should let you check

  • A no-income-tax state. Texas on $3,000.00 biweekly returns net pay of $2,450.12.
  • A state with disability insurance. California on the same pay returns $2,277.06.
  • A city tax. Columbus, Ohio returns $2,299.35.
  • A validation failure, by sending a decimal amount, to see your error handling work.
  • A year-to-date cap, by sending a Social Security year-to-date figure near the wage base.

Moving to production

Switching from a test key to a live key changes only the key. The endpoint, the request and the rules are identical. See the integration guide for the order to build in.

Is the test data real?

Does the test environment cost anything?

No. The browser calculator needs no key once you are signed in, and test keys are never billed.
