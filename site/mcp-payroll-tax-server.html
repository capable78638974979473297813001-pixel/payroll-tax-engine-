MCP server for payroll tax

Give an AI assistant or agent the real payroll tax engine as tools, instead of letting it guess the rules.

Language models are unreliable at payroll tax arithmetic: the rules are specific, dated and local. The Omnia.tax MCP server hands an assistant the actual engine as tools, so it calls the calculation and reports the result rather than reciting a rate from memory.

The tools

ToolWhat it doesBilled as
calculate_paycheckOne paycheck: every federal, state, local and employer tax line, and net pay.1 paycheck
compare_paychecksTwo paychecks and a step-by-step explanation of the difference.2 paychecks
gross_upThe gross pay that leaves a target take-home amount.1 paycheck
employer_taxesNew York MCTMT and the Nevada Modified Business Tax from a quarter's payroll.Not billed
lookup_addressA work and home address to the state, local jurisdictions and certificate.Not billed
coverageThe states and tax year the engine can compute.Not billed

How it connects

The server is at https://api.omnia.tax/mcp, speaks the Model Context Protocol over streamable HTTP with one JSON-RPC message per request, and authenticates with the same bearer key as the REST API. Per-key rate limits and billing match the REST endpoints, and a refused call is not billed. A test key works too, unbilled.

Why use it

  • An HR or finance assistant can answer "what does this offer take home in Ohio?" with an engine result.
  • Validation failures come back as tool results the model can read and fix, naming the field.
  • Every figure is the same one the REST API would return.

See the docs for the connection details.

Questions

What is an MCP server?

A Model Context Protocol server exposes tools that AI assistants and agents can call. Here the tools are payroll tax calculations.

Does the MCP server cost extra?

No separate fee. Each call is billed like the REST endpoint it matches: one paycheck for a calculation or gross-up, two for a comparison, and nothing for address lookups, employer-tax estimates or coverage.

Can an AI model calculate payroll tax on its own?

It should not. Rates, caps and local rules are specific and dated, and a model can state them with confidence and be wrong. Calling an engine gives a result you can trace.
