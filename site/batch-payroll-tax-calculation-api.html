Batch payroll tax calculation API

One request for a whole pay run.

A pay run is hundreds of paychecks. Posting them one at a time works, and a batch endpoint is neater. POST /v1/payCalc accepts an array of requests, or an object with a payCalc array, and returns an array of results. It follows the batch calling convention that the Symmetry-style adapter uses, so integrations that already call that way look familiar.

Shape

POST /v1/payCalc
[ { …a payCalc request… }, { …another… }, … ]

or

{ "payCalc": [ { … }, { … } ] }

The response is an array of results in the same order. The body must be an array of requests; anything else is refused with invalid_json.

Billing

One usage unit per successful paycheck in the batch. A failed calculation counts for nothing. A batch of 200 is metered as 200 paychecks at $0.08 each ($16.00), the same as 200 single calls.

Single calls or batch?

UseWhen
POST /v1/paycheckYou want the full response shape, notices and warnings, and one result per request.
POST /v1/payCalcYou are integrating with a Symmetry-shaped client, or you want a single request for a run.

Know the limits

  • The batch adapter uses its own jurisdiction ids, not Symmetry's. See migrating from a payCalc integration.
  • Rate limits apply per request, so a large batch is one call against the limit.
  • Keep batch sizes reasonable so one slow paycheck does not hold up the rest.

Questions

Can I calculate many paychecks in one request?

Yes. POST an array of requests, or an object with a payCalc array, to /v1/payCalc and you get an array of results in the same order.

How is a batch billed?

One usage unit per successful paycheck in the batch.
