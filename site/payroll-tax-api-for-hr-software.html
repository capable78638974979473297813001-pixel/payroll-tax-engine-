Payroll tax API for HR software

Take-home and cost numbers in the places HR software shows pay.

HR software shows pay in many places that are not payroll runs: offer letters, compensation bands, relocation estimates, total-rewards statements. In each, the useful number is what the person takes home and what the role costs the employer. Those need tax rules by location and year, which a tax calculation API provides.

A relocation example

An employee on $3,000.00 biweekly considers moving from Texas to California. The engine returns net pay of $2,450.12 in Texas and $2,277.06 in California, a difference of $173.06 per paycheck. The compare endpoint returns that difference already broken down line by line.

Employee-facing tools

Let employees see how a change to their W-4 or a pre-tax benefit election changes take-home before they commit. Each change is a re-run of the same request with one field altered, and the comparison explains it in order.

What it does not do

It does not hold employee records, run payroll or file anything. It is the calculation layer you call from the screens above. For employee cost modelling with the employer's side included, see the true cost of an employee.

Questions

How can HR software use a payroll tax API?

To show take-home pay on offers, employer cost on compensation plans, before-and-after paychecks for relocations and W-4 what-ifs for employees, all by calling the engine with the person's location and pay.

Does it store employee data?

The calculation API is stateless: you send the facts of a paycheck and get a result. It is not an employee records system.
