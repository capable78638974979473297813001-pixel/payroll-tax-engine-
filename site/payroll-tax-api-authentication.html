Payroll tax API authentication

One header, two kinds of key.

The API authenticates with a bearer key sent in the Authorization header. There is no OAuth dance and no signature to compute. What matters is which kind of key you hold and where you keep it.

The header

Authorization: Bearer sk_test_…

Two kinds of key

KeyUse
sk_test_…Development and CI. Same engine and data as live. Never billed. 30 requests a minute, 500 a day.
sk_live_…Production. Billed at $0.08 per paycheck calculation after the 14-day trial. Needs a payment method on file.

Keeping a key safe

  • Read it from an environment variable or a secrets manager. Never commit it.
  • Call the API from your server. A key in browser code can be copied by anyone who opens the page.
  • Use separate keys for separate environments so one can be revoked without breaking the others.
  • The full key is shown once when it is issued, and only a hash is stored. Only a short prefix is shown afterwards.
  • A test key expires after 90 days. A new key replaces the previous key of the same kind and never the other kind.
  • Every response from an accepted key carries an Omnia-Mode header, live or test, so you can see which kind you used.

What the 401s mean

CodeMeaning
missing_keyNo Authorization: Bearer header was sent.
invalid_keyThe key is not recognised or was revoked.
expired_keyThe key has passed its expiry. Issue a new one.

A 402 with payment_method_required is different: the key is valid, but a live key needs a payment method or an active subscription. Check which key you are using with GET /v1/me, which returns the key's details and recent usage.

Questions

How do I authenticate to the payroll tax API?

Send your key as a bearer token in the Authorization header: the word Bearer, a space, then the key. Test keys start sk_test_ and live keys start sk_live_.

Can I put the key in front-end code?

No. Anyone who opens the page could copy it. Call the API from your server.
