Payroll tax MCP tools

What an AI agent can do once it is connected.

Model Context Protocol lets an AI assistant call a tool instead of guessing. Language models are poor at payroll arithmetic and worse at knowing which rate applies in which town. Connecting one to the Omnia.tax MCP server gives it the engine itself, so the answer it gives is the one the API returns.

The tools

ToolWhat it doesBilling
calculate_paycheckOne paycheck: every tax line and net pay.One paycheck
compare_paychecksTwo paychecks and why they differ.Two paychecks
gross_upThe gross pay that leaves a target take-home amount.One paycheck

How it connects

The server is the POST /mcp endpoint, speaking JSON-RPC 2.0 over streamable HTTP. It supports initialize, ping, tools/list and tools/call, and authenticates with the same bearer key as the REST API. See the MCP server page for setup.

Why an agent should call it

Ask a model what a $3,000.00 biweekly check in Columbus, Ohio nets and it will estimate. Call the tool and the answer is $2,299.35, with federal income tax of $320.38 and a line for the city tax. The estimate and the engine can differ by tens of dollars on a single check.

Use a test key first

An agent can loop faster than a person. Give it a test key while you build, because it is never billed and capped at 30 requests a minute.

Questions

What tools does the MCP server expose?

calculate_paycheck, compare_paychecks, gross_up, employer_taxes, lookup_address and coverage.

How are MCP tool calls billed?

Like the matching REST endpoint: one paycheck for calculate_paycheck and gross_up, two for compare_paychecks, and nothing for employer_taxes, lookup_address or coverage.
