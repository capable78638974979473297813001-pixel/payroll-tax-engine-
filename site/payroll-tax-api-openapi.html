Payroll tax API OpenAPI spec

One document describes every endpoint, field and error.

The Omnia.tax API is described by an OpenAPI 3.1 document, served as JSON at https://api.omnia.tax/v1/openapi.json. It is generated from the same definitions the server validates against, so it describes what the API does rather than what someone remembered to write down.

What you can do with it

  • Generate a typed client in the language your payroll or HR product is written in, using any OpenAPI 3.1 generator.
  • Import the document into an API client such as Postman or Insomnia to try each endpoint with a key.
  • Validate a request in your own tests before it leaves your code, using the request schema inside it.
  • Feed it to an AI coding assistant so the integration it writes uses the real field names.

Examples are real

The examples inside the document are not hand-typed. They are requests the engine runs. The paycheck example for Texas returns net pay of $2,450.12 on $3,000.00 gross, and if the rules change that figure changes with them.

Staying in step

Every response carries an X-Omnia-Version header, and the changelog lists what changed in each release. Pin your generated client to a version you have tested and regenerate it when you choose to.

Questions

Where is the OpenAPI document?

At https://api.omnia.tax/v1/openapi.json, and also at /openapi.json. It is OpenAPI 3.1.

Can I generate a client from it?

Yes. Any OpenAPI 3.1 generator can produce a typed client. The request schema is also published separately as JSON Schema.
