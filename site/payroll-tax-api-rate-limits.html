Payroll tax API rate limits

What the limits are, how to see them, and how to back off.

Rate limits protect the service and tell you how fast you can safely call it. Omnia.tax limits calls per minute for every key, and caps test keys per day as well. The limits are visible on every response, so a client never has to guess.

Test keys

LimitValue

BilledNever

Live keys

A live key has a higher per-minute limit and no daily cap. Billing is $0.08 per paycheck calculation after the 14-day trial, so volume is limited by speed, not by a quota you must buy in advance.

What a response tells you

  • RateLimit-Limit: calls allowed in the window.
  • RateLimit-Remaining: calls left in this window.
  • Retry-After: on a 429, the seconds to wait.

Backing off

async function calc(body, attempts = 4) {
  for (let i = 0; i < attempts; i++) {
    const res = await fetch(URL, { method: "POST", headers, body: JSON.stringify(body) });
    if (res.status !== 429) return res;
    const wait = Number(res.headers.get("Retry-After") ?? 1);
    await new Promise((r) => setTimeout(r, wait * 1000));
  }
  throw new Error("still rate limited");
}

For a payroll run, send calls through a small queue sized to your limit, not all at once. A run of 500 paychecks at 30 a minute on a test key takes about 17 minutes; ask for a live key when you need to run at production speed.

Questions

What are the rate limits on test keys?

30 requests a minute and 500 a day. The daily cap resets at midnight UTC. Test calls are never billed.

What do I do on a 429?

Wait the number of seconds in the Retry-After header, then retry. Calls are stateless, so a retry returns the same answer.

Is there a daily limit on live keys?

No. Live keys have no daily cap, only a per-minute limit.
