REST API for payroll taxes

Plain HTTP and JSON. No SDK required.

If you want to calculate payroll taxes from any language, a REST API is the lowest-friction shape: an HTTPS request, a JSON body, a JSON answer. Omnia.tax follows ordinary conventions so a client written in an afternoon behaves the same as one written in a week.

Conventions

ConventionWhat Omnia.tax does
TransportHTTPS only, https://api.omnia.tax.
AuthenticationA bearer key: Authorization: Bearer $KEY.
BodiesJSON in, JSON out, Content-Type: application/json.
MoneyInteger cents, never decimals.
DatesISO yyyy-mm-dd. The check date selects the tax year.
Success200 with the result in a result object.
Client mistakes400 for bad JSON, 401 for key problems, 402 for billing, 422 for input the engine rejects, 429 for rate limits.
Rate limitsRateLimit-Limit and RateLimit-Remaining headers, and Retry-After on a 429.

The core request

Every calculation starts from the same body. This one asks for a $3,000.00 biweekly check for an employee who lives and works in Columbus, Ohio:

curl https://api.omnia.tax/v1/paycheck \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "checkDate": "2026-09-15",
  "payFrequency": "biweekly",
  "earnings": [{ "code": "REG", "category": "regular", "amount": 300000 }],
  "deductions": [],
  "federalW4": { "filingStatus": "single", "multipleJobs": false,
    "dependentCredit": 0, "otherIncome": 0, "deductions": 0, "extraWithholding": 0 },
  "ytd": { "socialSecurity": 0, "medicare": 0, "futa": 0 },
  "workState": { "code": "OH", "certificate": { "residenceCity": "Columbus", "workCity": "Columbus" } }
}'

What comes back

State and city tax appear as their own lines. For Columbus the response includes Ohio Income Tax ($75.77) and Ohio Municipal Income Tax ($75.00), next to federal income tax of $320.38.

Stateless by design

Nothing is stored between calls. Year-to-date wages come in on each request in the ytd object, so you can retry a call or replay it for an audit and get the same answer. See how year-to-date wages work.

Questions

Is there a REST API for payroll taxes?

Yes. Omnia.tax exposes the payroll tax engine as a JSON REST API over HTTPS with bearer-key authentication.

Do I need an SDK?

No. Any language that can send an HTTPS request with a JSON body works. The OpenAPI document can generate a typed client if you want one.

Which status code does a validation failure return?

422 with the code invalid_input and a details array naming each invalid field. Malformed JSON returns 400.
