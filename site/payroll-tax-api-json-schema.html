Payroll tax API JSON Schema

Validate a paycheck request on your side, before it is sent.

The paycheck request is published as a JSON Schema at https://api.omnia.tax/v1/schemas/paycheck-request.json. Using it in your own code catches a wrong type or a missing field at the point you build the request, instead of as a 422 from the network.

Where it helps

  • Form and import validation. An imported spreadsheet of pay data can be checked against the schema row by row before anything is sent.
  • Unit tests. Assert that every request your payroll code can build validates against the schema.
  • Editor support. Point your editor at the schema for autocompletion while you write fixtures.

What the schema enforces

Amounts are integers (cents), dates are ISO dates, and categories come from a fixed list. The server runs the same checks, so a request that passes the schema will not be refused for its shape. The schema is permissive about extra top-level properties, so a misspelt optional field is not an error by itself; assert on the fields you mean to send in your own tests.

What it cannot check

A schema checks shape, not meaning. Whether a state needs a particular certificate answer for a given employee depends on the state's rules, so the server can still return cannot_compute naming the missing field. See the error codes.

An invalid request, as the server reports it

{
  "error": "The request did not pass validation.",
  "code": "invalid_input",
  "details": [{ "path": "earnings[0].amount",
    "message": "must be integer cents, not 3000.5 — send whole cents (e.g. 300050 for $3,000.50), never dollars." }],
  "requestId": "req_01J9Z6Q8X3"
}

Questions

Is there a JSON Schema for the payroll tax request?

Yes, at https://api.omnia.tax/v1/schemas/paycheck-request.json. The OpenAPI document embeds the same definitions.

Does passing the schema guarantee a calculation?

It guarantees the shape is valid. A state can still need a certificate answer the schema cannot know about, in which case the API returns cannot_compute and names the missing field.
