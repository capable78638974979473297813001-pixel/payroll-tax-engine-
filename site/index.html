03
No guessing
EXPLICIT, ALWAYS

Never asilent $0.

If a rule or code is missing, the API returns an explicit error or a “not modelled” line. It never fills the gap with a quiet zero, so a missing tax can’t hide inside a clean-looking paycheck.

A · A not-modelled line Illustrative 
{
  "name": "IN County Income Tax",
  "amount": 0,
  "detail": "NOT MODELLED — no county specified. Do not treat as zero-tax."
}
B · Or an explicit error 
{ "error", "code", "requestId" }

Every error has the same shape. See the Errors table in the docs.

Developers
POST /V1/PAYCHECK

Your first paycheck in one request.

Send the paycheck as JSON. Get back every tax line in the same response.

ENDPOINTPOST /v1/paycheck
AUTHBearer secret key
BODYapplication/json
AMOUNTSInteger cents
REQUESTcURL
curl -X POST https://api.example/v1/paycheck \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
  "checkDate": "2026-08-15",
  "payFrequency": "biweekly",
  "earnings": [{ "code": "REG", "amount": 100000 }]
}'
RESPONSE200
Field names
result › checkDate › grossPay › pretaxDeductions › posttaxDeductions › employeeTaxTotal › employerTaxTotal › netPay › taxes[] › id · name · payer › jurisdiction › taxableWages › amount · detail

Amounts in integer cents.

100000 = $1,000.00
05
The fine print
INCLUDED IN THE PRICE

The fine print is short,and it’s all in your favor.

01

One call, every tax line

Federal, state, and local lines come back together in a single response. No stitching calls together.

02

Integer cents

Every amount is a whole number of cents. No floating-point rounding, ever.

03

Effective-dated rates

A check dated before a rate change uses the rate that was in effect on that date.

04

Garnishments & minimum wage

Wage garnishments and minimum-wage checks are included in the same calculation.

05

No third-party dependencies

The calculation runs with no third-party dependencies.
