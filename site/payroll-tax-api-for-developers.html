Payroll tax API for developers

The parts of the API an engineer checks before committing to it.

Engineers evaluating a payroll tax API ask a different set of questions than a payroll manager does. Can I generate a client from a spec? Are amounts safe to add up? What does a failure look like, and can my code branch on it? Can I try it without a sales call? This page answers those for Omnia.tax with links to the documents that prove each answer.

A published contract

  • An OpenAPI 3.1 document describes every endpoint, request and response, with examples.
  • A JSON Schema for the paycheck request, so you can validate before you send.
  • An X-Omnia-Version header on every response, and a changelog.

Predictable behaviour

  • Integer cents. Every amount, in and out. Dollars with a decimal are refused with the field named.
  • Stable error codes. Each error body has a code to branch on and a message for a person. See the error codes.
  • Field-level validation. A bad request returns a details array naming each field and why.
  • A request id on every response in the X-Request-Id header, to quote to support.

Endpoints

EndpointWhat it does
POST /v1/paycheckOne paycheck: every tax line and net pay. Also answers garnishment and minimum-wage checks in the same call.
POST /v1/paycheck/compareTwo paychecks and an explanation of the difference, step by step.
POST /v1/paycheck/gross-upThe gross pay that leaves a target take-home amount.
POST /v1/employer-taxesQuarterly employer taxes on total payroll: New York MCTMT and the Nevada MBT.
POST /v1/addressA work and home address turned into a state, local jurisdictions and certificate. Recorded, not billed.
GET /v1/statesThe states with rules for a tax year. No key needed.
POST /mcpA Model Context Protocol server for AI agents.

Questions

Does the payroll tax API have an OpenAPI spec?

Yes. It publishes an OpenAPI 3.1 document at /v1/openapi.json and a JSON Schema for the paycheck request at /v1/schemas/paycheck-request.json.

Can I try the API without paying?

Yes. Test keys use the same engine and data as live keys, need no card, and are never billed. They are capped at 30 requests a minute and 500 a day.

Are the amounts safe to add up in code?

Yes. Every amount is an integer number of cents, so sums are exact and nothing depends on floating-point rounding.
