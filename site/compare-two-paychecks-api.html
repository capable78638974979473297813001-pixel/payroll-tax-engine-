Compare two paychecks and explain the difference

A raise, a move, a new deduction: the compare endpoint attributes the change in net pay to each input that changed.

Why did this employee's net pay change? POST /v1/paycheck/compare takes two paychecks, or one paycheck and the fields that changed, and attributes the difference.

How the explanation is built

It is not a guess. The inputs are diffed, then each difference is applied to the first paycheck one at a time, in a fixed order, and the engine is re-run after each. What a step moves is exactly what that change did given the changes before it, and the steps add up to the whole difference. When two changes interact, another order can split the credit differently; the total is the same.

A worked example: a move from Texas to California

The same $3,000.00 biweekly employee, moving from Texas to California. Net pay goes from $2,450.12 to $2,277.06, a drop of $173.06.

workState.code: TX → CA. Net pay goes down $173.06. TX_SUI_ER (employer) −$81.00, CA_SIT +$134.06, CA_SUI_ER (employer) +$102.00, CA_DBL_EE +$39.00.

Tax ids with _ER are employer taxes; they appear in the explanation but do not change take-home pay.

The request

POST /v1/paycheck/compare
{ "before": { ...a paycheck request... }, "change": { "workState": { "code": "CA" } } }

Send after for a full second request, or change for only the fields that differ. Billed as two paychecks.

Questions

How can I see why my net pay changed?

Compare the two paychecks tax by tax. The compare endpoint does this by applying each changed input to the earlier paycheck in turn and re-running the engine, so each step shows exactly what that change moved.

Does the order of changes affect the explanation?

It can, when changes interact: a raise and a filing status both move the bracket, so the credit between them can split differently in another order. The total difference is always the same.
